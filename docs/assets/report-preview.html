Summary

The application exposes its internal Git repository directory (.git) to public access, allowing attackers to download the entire source code history and retrieve sensitive configuration data, including cloud credentials.

Description

The web server is configured to allow HTTP requests to the .git directory. This vulnerability allows an unauthenticated attacker to use tools like git-dumper to extract the full repository contents. Furthermore, analysis of commit history revealed that sensitive AWS access keys were committed and are publicly retrievable via this exposure.

Steps to reproduce

  1. Send a GET request to /.git/HEAD
  2. Use a tool (e.g., git-dumper) against the exposed directory path to download the full source code repository.

Impact

An attacker can gain access to proprietary source code, intellectual property, and highly sensitive cloud credentials (AWS keys). Successful exploitation allows an attacker to compromise backend infrastructure, leading to unauthorized resource usage, data exfiltration, or service disruption.

Remediation

  • Configure the web server (e.g., Apache, Nginx) to explicitly deny all public access requests to directories named .git and other version control system folders.
  • Implement pre-commit hooks and secret scanning tools (e.g., git-secrets) to prevent sensitive credentials from ever being committed to the repository history.
